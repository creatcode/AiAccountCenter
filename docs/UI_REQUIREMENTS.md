# 界面与交互要求

日期：2026-10-13。沿用 workbuddy-switch 的界面基础，扩展新平台和服务器模式；本文不是已实现界面或截图验收报告。

## 1. 基本方向

保留上游侧栏、账号卡片、信息密度、组件和主题体系。平台扩展优先修改现有账号页/卡片与通道适配，不复制三套页面或另建视觉组件库。

使用中文产品文案，区分“登录凭据”和“模型 Token 用量”。界面不向用户堆叠 Rust、SQLite 表名、原项目内部路径等实现细节。

代码开发前先读上游 UI 与实际生效技能/设计指令；需要维护 DESIGN.md 或交互契约时以已导入的组件/令牌为依据，不在文档阶段虚构运行样式或已验证设计系统。

## 3. 平台和运行模式

WorkBuddy 国内/国际明确区分，Trae Work/Trae CN 的客户端与账号关系清晰，Qoder OAuth/PAT 的能力差异可见。

能力来自后端运行模式与平台/客户端探测，不靠浏览器系统字符串猜测。Web 不展示客户端/会话/Hook/CLI/悬浮窗入口；直接访问仍由后端拒绝。

不支持的地区/任务/凭据组合明确说明原因，不展示无法执行的成功按钮。缺本地用量显示“未接入/当前模式不可用”，不能显示为零。

## 4. 账号与批量操作

- 保留上游卡片结构，稳定显示平台/区域、身份、凭据状态、积分/到期、最后更新时间及必要操作。
- 加载中固定卡片/按钮几何，避免刷新时布局跳动。
- 搜索支持中文输入法，不在 composition 中提交；非空搜索有可键盘操作的清空按钮，清空立即生效。
- 筛选/排序/已提交搜索可恢复到 URL 非敏感参数，不把 Token、邮件正文或秘密写入地址。
- 切换平台/筛选时明确选择范围；批量按钮标明实际账号数，隐藏筛选外的已选对象不能被悄悄执行。
- 删除、覆盖导入、客户端切换/恢复等有明确对象和后果的确认；普通保存/刷新不反复确认。
- 长昵称、错误和备注可截断并查看完整信息，不能把主操作挤出视口。

## 5. 异步任务和状态

加载、空数据、无搜索结果、部分失败、全部失败、执行中、待核查、成功和取消分别处理。

手动触发任务后展示后端运行状态，不把“请求已接受”显示为“领取成功”。国际会话执行结束与奖励确认分开。按钮防重复提交，禁用/忙碌原因清楚，尺寸不变。

浏览器刷新/关闭不影响后台执行；重新访问从持久记录恢复状态。网络断开时显示数据可能过期，不将旧状态当新结果。

修改计划/Webhook 时保留未保存草稿。轮询通知状态或标记已读只更新相关结果，不能覆盖未保存设置。离开有草稿的页面时给应用内提示。

通知失败不改变任务的成功状态；关键错误保留在详情/历史，不能只出现短暂 Toast。

## 6. 登录、导入与敏感信息

密码、Token/PAT、Webhook 密钥默认遮蔽；显示/隐藏按钮有明确可访问名称，提交后不在普通详情回显秘密。

导入前展示文件版本、账号数量、重复策略及将覆盖的对象；损坏/错误口令定位清晰，失败保留现库。浏览器下载通过受保护的数据流，不接受任意服务端输出路径。

会话过期后保留非敏感草稿，重新登录不自动重放危险操作。OAuth 轮询可取消、有过期提示，远程回调不可用给可行替代方式。

## 7. 统一交互与可访问性

复用上游 Radix 等维护中的组件。使用语义 button/link、可见焦点、可访问名称、文本错误与状态，颜色不能是唯一信息。

应用内确认/弹窗使用现有可访问组件，不用浏览器 alert/confirm/prompt。正确处理焦点、Esc、背景与返回焦点；高风险确认默认聚焦安全动作。WebView2 缺失等发生在界面创建前的启动故障例外，使用不依赖 WebView 的原生对话框，不能等待 React 加载后才显示错误。

表格/列表的排序、分页、选择和无结果状态一致。滚动归属清晰：长表内部滚动不锁死旁边表单；切页/切 Tab 不继承错误高度。

窄视口和长中文内容可用；遵循系统减少动画设置，检查主题对比度。悬浮窗实际验证可拖动、位置保存、显示/隐藏与键盘替代。

### 7.1 Windows 启动与修复提示

启动时区分运行时缺失、版本过低、安装取消、网络/权限失败、profile 不可写和环境创建失败。中文提示说明实际原因及下一步，提供与故障匹配的官方获取/离线安装说明、明确安装或修复选择、重新检测和退出；不显示无响应空窗口。

安装器说明 WebView2 是桌面所需组件；用户同意流程后自动处理已有/缺失状态，避免重复安装。主程序不暗中安装或循环请求提权。错误诊断包含可复制的脱敏错误码/版本信息，不暴露账号凭据、私人会话或完整用户路径。

修复前不启动真实后台任务、Hook 或客户端写入。独立 Web 版的运行要求单独说明，不将其当自动降级模式，不因桌面失败开放端口。

界面完成必须有真实浏览器/原生窗口运行证据，不能以 TypeScript 编译、静态截图或演示数据代替产品流程。
